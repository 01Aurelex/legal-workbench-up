# 法岩律师本地工作台 · 桌面端加固构建说明

适用版本：**v0.9.12**（已去除授权体系、已修复提醒中心「已知悉」）
交付形态：**Windows 原生桌面安装包（NSIS `.exe`）**——独立窗口运行，**不依赖浏览器**
文档定位：本文件是构建管线的**权威说明**。改动 `build/` 下任何脚本后，必须回来同步本文件。

> 2026-09-17 变更：按需求调整为「不依赖浏览器、具备独立操作界面的桌面安装包」。
> 采用 **Tauri v2（Rust 原生外壳 + WebView2）** 承载界面，Python 后端以 **sidecar**
> （内置伴随进程）形式嵌入安装目录；**macOS 桌面端已放弃**，不再构建。

---

## 一、整体架构

```
┌──────────────────────────────────────────────────────────┐
│  NSIS 安装包  法岩律师本地工作台_0.9.12_x64-setup.exe      │
│  ├─ 法岩律师本地工作台.exe   （Rust/Tauri 原生外壳，有窗口）│
│  ├─ WebView2 引导器（embedBootstrapper，静默安装）         │
│  └─ resources\                                            │
│     └─ sidecar\                                           │
│        ├─ legal-workbench.exe   （Python 后端，无控制台）   │
│        └─ _internal\            （原生 .pyd + 完整性清单）  │
└──────────────────────────────────────────────────────────┘
```

启动时序：

1. 双击 → Rust 外壳启动，创建 **1440×900 独立窗口**（非浏览器标签页，无地址栏）；
2. 外壳生成 64 位十六进制一次性令牌，通过环境变量 `LW_AUTO_TOKEN` 注入后端，
   同时设 `LW_NO_BROWSER=1`（后端**不会**调用系统浏览器）；
3. 窗口先显示内置的 `loading.html` 启动页；
4. 外壳轮询 `127.0.0.1:8765`（最长 90 秒），就绪后把窗口切到
   `http://127.0.0.1:8765/?token=…`；
5. 关闭窗口 → 外壳 kill 后端进程，任务管理器无残留；
6. 单实例插件保证重复启动只聚焦已有窗口。

界面内容由后端在**回环地址**上提供，外壳不加载任何远程页面，release 版不含 devtools。

## 二、加固层次（反编译 / 反逆向）

| 层次 | 措施 | 效果 |
|---|---|---|
| 1. 源码级 | 业务模块与入口**全部**经 **Cython 3** 编译为原生机器码（`.pyd`） | 发行包内**不存在**这些模块的 Python 源码与 `.pyc`，`uncompyle6` / `pycdc` / `decompyle3` 无法还原业务逻辑 |
| 2. 外壳级 | 界面与启动逻辑是 **Rust 编译产物**（`panic=abort`、`lto=thin`、`strip=true`） | 外壳本身无脚本可反编译，符号表已剥离 |
| 3. 完整性 | 构建后生成 `integrity.json`（HMAC-SHA256 签名），启动时由已编译进机器码的 `guard` 模块校验 | 增删、替换、打补丁任一原生模块都会导致启动拒绝 |
| 4. 反调试 | Windows：`IsDebuggerPresent` / `CheckRemoteDebuggerPresent` / `NtQueryInformationProcess` | 附加调试器即静默退出，无法动态跟踪 |
| 5. 运行时 | 单实例端口锁；后端以 `CREATE_NO_WINDOW` 拉起；令牌不落盘 | 无控制台闪窗、无多开写坏数据库、抓不到长期令牌 |
| 6. 数据面 | 数据库、密钥、配置全部落在安装目录 `data\`，本地 AES 密钥 + 本机令牌 | 不写注册表、不落用户目录 |

> 说明：任何软件都无法做到"绝对不可逆向"。以上措施把门槛从
> 「解包即得源码」提高到「需逆向 x64 机器码（Python 业务 + Rust 外壳）并绕过完整性校验」。
> 若需更高强度，可对外层 exe 再加 VMProtect / Themida 壳（商业工具）。

> 注意：PyInstaller **6.0 起已移除** `--key` / `cipher` 字节码加密
> （`RemovedCipherFeatureError`），本项目改用「全面原生化」替代该层。

## 四、构建步骤（Windows）

### 0. 前置条件

| 依赖 | 版本 | 说明 |

| Visual Studio 2022 生成工具 | MSVC 14.44 | Cython 编译需要；脚本自动探测并注入 INCLUDE/LIB/PATH |
| Rust 工具链 | cargo/rustc 1.98.1 | Tauri 外壳编译 |
| Node.js | 22.x | 运行 `@tauri-apps/cli` |

### 1. 构建 Python 后端 sidecar

```powershell
# 在仓库根目录执行（脚本自动探测并注入 MSVC 环境，无需先跑 vcvars）
python -X utf8 build\build_all.py --sidecar
# 或使用包装脚本：
powershell -ExecutionPolicy Bypass -File tools\build_sidecar.ps1
```

产物：`build\out\legal-workbench\`（约 118 MB）
含 `legal-workbench.exe` + `_internal\`（28 个原生 `.pyd`、`integrity.json`、前端资源）。

冒烟测试（推荐直接用脚本，自动绕过环境代理、自动读取 `data/config.json` 的端口）：

```powershell
python -X utf8 build\_smoke_ws.py `
   "build\out\legal-workbench\legal-workbench.exe"
# 期望输出 VERDICT: PASS；结果同时写入 build\_smoke_ws.txt
```

手动方式：

```powershell
$env:LW_NO_BROWSER="1"; $env:LW_AUTO_TOKEN="smoketoken…"
Start-Process "…\legal-workbench.exe" -WorkingDirectory "…\legal-workbench"
Invoke-WebRequest http://127.0.0.1:8765/                 # 应 200
Invoke-WebRequest http://127.0.0.1:8765/api/bootstrap    # 应返回 {"ok":true,"token":"…"}
```

### 2. 同步 sidecar 到 Tauri 资源路径

**仓库版本无需手工同步**：`tauri.conf.json` 里 `bundle.resources` 把
**`../build/out/legal-workbench`**（相对 `src-tauri`）映射为安装后的 `sidecar/`，
而构建产物本来就落在 `<仓库根>\build\out\legal-workbench`，两者天然对齐。

（历史做法是把产物从仓库外的构建树 robocopy 进来；现在构建树就在仓库内，该步骤已删除。）

### 3. 编译外壳并打安装包

```powershell
# 在仓库根目录执行
$env:PATH = "$env:USERPROFILE\.cargo\bin;" + $env:PATH
node node_modules\@tauri-apps\cli\tauri.js build
# 或使用包装脚本（会先自动构建 sidecar）：
powershell -ExecutionPolicy Bypass -File tools\build_tauri.ps1
```

> 改过 `src-tauri/icons/` 或 `build/out/` 内容后，**必须先 `touch src-tauri\build.rs`**
> （见 3.1 节的坑），否则新的图标/资源不会被打进安装包。

产物：

| 文件 | 路径 |
|---|---|
| NSIS 安装包 | `src-tauri\target\release\bundle\nsis\法岩律师本地工作台_0.9.12_x64-setup.exe` |
| 免安装版 exe | `src-tauri\target\release\法岩律师本地工作台.exe`（需同目录 `resources\sidecar`） |

NSIS 配置：简体中文界面、`currentUser` 安装模式（无需管理员权限）、LZMA 压缩。

### 3.1 图标与安装向导美术（2026-09-18 补充）

### 3.2 启动崩溃修复：`cannot import name '__version__' from 'websockets'`（2026-09-17 定位 / 09-18 验证）

**现象**：安装后双击，窗口停留在加载页；`frozen_main.py` 抛

```
File "uvicorn\config.py", line 504, in load
File "uvicorn\importer.py", line 19, in import_from_string
File "uvicorn\protocols\websockets\auto.py", line 19, in <module>
ImportError: cannot import name '__version__' from 'websockets' (unknown location)
```

**根因**（两层叠加）：

1. 打包产物 `_internal\` 里落了一个**残缺的** `websockets\` 目录——只有
   `speedups.cp313-win_amd64.pyd`，**没有 `__init__.py`**。Python 于是把该目录
   当作 **namespace package**，`import websockets` 会"成功"返回。
2. uvicorn 的 `protocols/websockets/auto.py` 结构是：

   ```python
   try:
       import websockets            # ① 能 import 成功（namespace package）
       ...
   except ImportError:
       AutoWebSocketsProtocol = None
   else:
       from uvicorn.protocols.websockets.websockets_sansio_impl import ...  # ② 这里才炸
   ```
   第 ②步内部 `from websockets import __version__` 抛出的 `ImportError`
   **不在 ① 的 try 保护范围内**，于是直接冒泡终止启动。
   而 uvicorn 的 `import_from_string()` 只捕获 `ModuleNotFoundError`，也兜不住。

**三层修复**（缺一不可，`legal-workbench.spec` + `frozen_main.py` + `build_all.py`）：

| 层 | 位置 | 措施 |
|---|---|---|
| 构建期 | `legal-workbench.spec` `excludes` | 排除 `websockets` / `wsproto` 及其全部子模块，杜绝"半收集" |
| 构建期 | `legal-workbench.spec` `hiddenimports` | 移除 `uvicorn.protocols.websockets.auto`（不再需要） |
| 运行期 | `server/frozen_main.py` | `uvicorn.run(..., ws="none")` —— **釜底抽薪**，压根不加载 WS 协议 |
| 构建后 | `build_all.py` | 扫描 `_internal`，发现任何 `websockets*` / `wsproto*` 残留即改名 `.__disabled` |
| 运维 | `server/frozen_main.py` | `_write_crash()`：windowed 无控制台时把完整栈写入 `data/startup_error.log` |

> 为什么 `ws="none"` 是安全的：本应用**无任何 WebSocket 端点**，前端只用 HTTP 轮询
> （已 grep 前端全部资源，`WebSocket|ws://|wss://|EventSource` 零命中）。
> uvicorn 侧 `WS_PROTOCOLS = {'none': None}`，`import_from_string(None)` 因
> `if not isinstance(import_str, str): return import_str` 直接返回，**完全不会 import 该模块**。

负面回归测试（主动注入残缺包，验证修复真的生效）：

```powershell
& <python> -X utf8 "D:\法律工作台\build\_smoke_ws.py" `
   "D:\法律工作台\build\out\legal-workbench\legal-workbench.exe" 8765 --inject-broken-ws
# 期望：_internal\websockets 被指向 namespace package，但 GET / 与 /api/bootstrap 仍 200，VERDICT=PASS
```

实测结果（2026-09-18）：

| 项目 | 结果 |
|---|---|
| sidecar 构建 | 成功，251 秒，118.0 MB，28 个原生 `.pyd`，`integrity.json` 29 文件 |
| `_internal` WebSocket 残留 | 空 |
| 常规冒烟 | `GET /` 200、`/api/bootstrap` → `{"ok":true,"token":"wstest"}`，无 `startup_error.log` |
| 注入残缺包后冒烟 | `find_spec` 确认 origin/loader 均为 None（namespace package，复现历史场景），后端仍 200 → **PASS** |
| 安装包内嵌 sidecar | 与构建产物 sha256 完全一致（`0d2ac3cc…`），包内 WebSocket 命中 0 处 |
| 图标回归 | 安装包 7 个 RT_ICON 与 `icons/icon.ico` 字节级完全一致 |

> 探测回环地址时必须 `urllib.request.ProxyHandler({})` 绕开环境代理，
> 否则 `127.0.0.1` 的请求会被代理吃掉、返回 **502 假失败**。

## 四·补、构建 macOS 版本（.dmg / .app）

macOS 包**只能由 macOS 构建**——PyInstaller、Cython 原生扩展、Rust 外壳都无法跨平台
交叉编译。两条路：

### A. 交给 GitHub Actions（推荐，零成本）

工作流 `.github/workflows/build-macos.yml`，矩阵同时产出两个架构：

| runner | 架构 | 面向机型 |
|---|---|---|
| `macos-15` | arm64 | Apple Silicon（M 系列） |
| `macos-15-intel` | x64 | Intel Mac |

> `macos-13` 系列已于 2025-12-04 全部退役，不要再引用；
> `macos-latest` 现在指向 macOS 15（arm64）。公开仓库的 macOS runner 免费且不限时长。

触发：Actions 页 → **build-macos** → `Run workflow`；或推送到 `main` 且改动命中
`build/ server/ frontend/ src-tauri/ tools/`。

### B. Mac 上本地构建

```bash
pip install -r requirements.txt cython pyinstaller
bash tools/build_sidecar.sh     # 产物 build/out/legal-workbench/legal-workbench
bash tools/build_tauri.sh       # 产物 src-tauri/target/release/bundle/{macos,dmg}/
```

### macOS 与 Windows 的差异清单（改代码时别漏）

| 位置 | Windows | macOS |
|---|---|---|
| sidecar 可执行文件名 | `legal-workbench.exe` | `legal-workbench`（**无后缀**） |
| `src-tauri/src/lib.rs` | `BACKEND_EXE` 走 `#[cfg(windows)]` | 走 `#[cfg(not(windows))]` |
| Tauri bundle 目标 | `tauri.conf.json` → `["nsis"]` | `tauri.macos.conf.json` → `["app","dmg"]` |
| App 图标 | `build/app.ico` | `src-tauri/icons/icon.icns`（`.ico` 不能作 macOS 图标） |
| Cython 扩展后缀 | `.pyd` | `.so`（`finalize_native.py` / `make_manifest.py` 已同时匹配） |
| 机器指纹来源 | MachineGuid + CPU ID + 磁盘序列号 | IOPlatformUUID + 机型标识 + 启动卷 UUID |
| Tesseract 可执行名 | `tesseract.exe` | `tesseract`（含 PATH 回退，兼容 Homebrew） |
| 本地大模型可执行名 | `llama-server.exe` | `llama-server` |
| 可写数据目录 | exe 同级 `data/`（绿色便携） | `~/Library/Application Support/法岩律师本地工作台/data/` |

**改动 `server/app/license.py` 的机器指纹算法时要格外小心**：Windows 分支的取值来源
与顺序必须保持不变，否则已签发的激活码会全部失效。

**数据目录为什么在 macOS 上要外置**（`server/app/config.py`）：
`.app` 对 macOS 用户是「一个文件」，其内部 `Contents/Resources/sidecar/` 可能只读
（直接从只读的 `.dmg` 运行、或装在非管理员账户的 `/Applications` 下），
**而且往已签名的 bundle 里写文件会破坏签名封条，应用可能直接打不开**；
覆盖安装又会整体替换 bundle，把用户数据一起清掉。因此冻结态 + `darwin` 时
`DATA_DIR` 指向 `~/Library/Application Support/<产品名>/data`，可用环境变量
`LW_DATA_DIR` 覆盖。内置引擎（`RESOURCES_DIR`）仍是只读资源，留在 exe 同级。
Windows 与源码模式的行为完全不变（回归测试见 `tests/`）。

### 签名与 Gatekeeper

- **Apple Silicon 上未签名的可执行文件会被系统直接杀掉**（`Killed: 9`），
  因此必须至少 ad-hoc 签名。脚本与 CI 都用 `APPLE_SIGNING_IDENTITY="-"`。
- `tauri.macos.conf.json` 里显式关掉 `hardenedRuntime`：没有公证时开启只会徒增权限
  摩擦（真要公证分发时再打开并配置 entitlements）。
- 用户首次打开需放行 Gatekeeper：

```bash
xattr -dr com.apple.quarantine "/Applications/法岩律师本地工作台.app"
```

- 想彻底消除提示需要 Apple Developer 账号（99 USD/年）做 Developer ID 签名 +
  `notarytool` 公证，属可选升级。
- CI 的「校验产物、sidecar 落位与签名」步骤会显式检查：
  sidecar 是否真的进了 `Contents/Resources/sidecar/`、外层 `.app` 是否为 adhoc 签名。
  这两处是最容易静默失败的地方。

## 六、已知坑（务必先看）

**1. Cython 化后必须显式声明 hiddenimports（最容易踩的坑）**
原生扩展对 PyInstaller 是黑盒，静态分析看不到扩展内部的 `import`。
漏声明会直接 `ModuleNotFoundError: No module named 'sqlite3'` 之类而**无任何日志**。
本工程已在 spec 的 `NATIVE_HIDDEN` 中补齐（`sqlite3`、`email.*`、`urllib.*`、`xml.*`、
`fastapi.*`、`starlette.*` 等）并对 fastapi/starlette/anyio/pydantic 做了 `collect_submodules`。
新增第三方依赖后请同步更新该列表。

**2. `main.py` 必须用 `annotation_typing=False`**
它含 FastAPI 路由签名（`files: list[UploadFile] = File(...)`）。默认编译会优化掉注解，
导致启动时 `TypeError: Expected list, got File`。
`build/build_main_native.py` 已在写入源码副本时注入文件级指令。

**3. 链接期缺 `rc.exe`**
精简安装的 VS 生成工具常缺资源编译器，链接 `/MANIFEST:EMBED` 会报 `LNK1158`，
脚本已统一追加 `/MANIFEST:NO` 规避。

**4. 构建顺序不能乱**
`prep_src.py` 会清空 `build\src`，所以必须
`prep_src → cythonize_app → finalize_native → build_main_native → PyInstaller → make_manifest`
依次执行；只跑 `prep_src` + `PyInstaller` 会得到只有 1 个文件的残缺 `integrity.json`。
直接用 `build_all.py` 可避免该问题。

**5. 沙箱/后台执行环境的注意点**
- `cmd.exe`、`reg.exe`、子进程继承 PATH 均受限：MSVC 环境必须在 Python 进程内注入；
- stdout/stderr 会被丢弃：日志必须写文件；
- 进程随命令结束被回收：启动 exe + HTTP 探测必须写在**同一条命令**内，
  或用后台任务。

**6. 分发体积**
sidecar 约 118 MB，NSIS 安装包经 LZMA 压缩后显著小于该值。
可选 AI / OCR / 语音引擎已在 spec 的 `excludes` 中排除（全部为函数内延迟导入，
不影响现有功能），如需恢复请从 `excludes` 移除并在 `collect` 列表中加回。

**7. 换图标后如何验证真的换上了（必做）**
历史上用一次性脚本（`_dump.py` / `_ico3.py`，用 pefile 解析 PE 资源）验证，这些脚本未随仓库发布，
可按同样思路自行复现：
- 外壳 exe：打印最大 RT_ICON 尺寸并统计金色像素数（旧图标约 2134，新天平图标约 6742）；
- 安装包：把 RT_GROUP_ICON + RT_ICON 重排成 .ico 再交给 Pillow；若解析结果是
  8bpp/4bpp 的 3 个条目 = 仍是 NSIS 默认图标；是 7 个 PNG 条目（256/128/96/64/48/32/16）
  = 已是本项目图标。
- 注意 `System.Drawing`（`Add-Type`）在本环境的沙箱里会被拦截，用 pefile 或 ctypes。

**8. 本机 safe-delete 策略会打断构建（2026-09-17 踩坑）**
本环境对删除操作有**每轮 50 次**的配额：`os.remove` / `os.replace` / `shutil.rmtree` /
`shutil.move` 全部计数，超限直接抛
`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 并以 `SystemExit` 中断
（**不是** `Exception`，普通 `try/except Exception` 兜不住，会导致整条流水线静默失败）。

因此 `build_all.py` 链路里**所有"删除"都改成了同卷 `os.rename`**，把文件移出发行树归档到：

```
build\_stripped_src\<MMDD_HHMMSS>\      ← cythonize_app / finalize_native / build_main_native
build\src_old_<MMDD_HHMMSS>\            ← prep_src 清空源树
build\out_old_<MMDD_HHMMSS>\            ← 每次 PyInstaller 覆盖 out\ 前
```

> 以上归档目录与 `build/out/`、`build/src/` 一样，均已在 `.gitignore` 中排除，
> 不会进入版本库。

这些归档目录只增不减（沙箱内无法批量清理），**构建若干次后需人工删除**，
否则磁盘会持续增长。规律：`os.rename` 不计数，其余都会。
另外：长构建（`tauri build`、PyInstaller）**必须前台执行**——批量删除的确认弹窗只在
前台工具调用里出现，放后台跑会直接失败；确认通过后该次工具调用内的删除不再计数。

**9. `main.py` 只能编译一次**
`cythonize_app.py` 会遍历 `server/app/*.py`，若不过滤 `main.py`，它会被编译两遍：
第二次 `build_main_native.py` 用 setuptools `build_ext --inplace` 覆盖时，setuptools 会先删掉
已存在的 `main.cp313-win_amd64.pyd` —— 白白消耗一次删除额度，且 `main.py` 源码已被移走导致
状态混乱。已在 `cythonize_app.py` 的 `SKIP` 中排除 `main.py`；因为跳过了，
`build_main_native.py` 需负责把 `main` 补进 `native_modules.txt`（否则它不进完整性清单）。

## 七、常见问题

**Q：杀毒软件报毒？**
无控制台的 PyInstaller 程序是误报重灾区。请使用 Windows 代码签名证书签名后提交白名单。

**Q：目标机没装 WebView2？**
安装包内置 `embedBootstrapper`，首次运行会**静默**引导安装 WebView2 Runtime；
若目标机完全离线，请改用 `offlineInstaller` 模式并把安装器一起打包。

**Q：端口 8765 被占用？**
后端会提示已在运行并退出。改端口：编辑安装目录 `data\config.json` 的 `port`
（同时需同步改 `src-tauri\src\lib.rs` 的 `BACKEND_PORT`）。

**Q：数据在哪里？**
全部在安装目录 `resources\sidecar\data\`（`currentUser` 模式默认在
`%LOCALAPPDATA%\法岩律师本地工作台\` 下）。卸载后如需保留，请先备份该目录。

**Q：macOS 版本？**
已按需求放弃，不再构建。`legal-workbench.spec` 仍保留 macOS 分支（BUNDLE / entitlements），
Tauri 外壳本身也跨平台，若后续需要，重编 sidecar 即可。
